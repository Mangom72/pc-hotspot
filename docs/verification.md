## 실제 삼성 폰에서 확인할 항목

| 순서 | 실행 | 기대 결과 |
|---|---|---|
| 1 | 안내대로 최초 등록 | 양쪽에 동일 번호 표시, PC `yes`와 폰 승인 필요, 완료 후 등록 모드 닫힘 |
| 2 | 앱 화면을 닫고 타일 열기·누르기 | 최신 상태 표시, 핫스팟이 꺼진 상태에서도 BLE로 켜짐 |
| 3 | 타일을 연속으로 누르기 | 처리 중 추가 입력 거부, 상태가 여러 번 전환되지 않음 |
| 4 | 폰 입력과 F9 두 번을 겹쳐 실행 | 한 요청만 실행, 겹치는 요청은 거부됨; 새 요청으로 상태 확인 가능 |
| 5 | 다른 Wi-Fi에 연결한 뒤 켜기 | 다른 Wi-Fi 연결 유지, 켜기 거절 |
| 6 | 폰 블루투스 끄기 또는 PC 범위 밖으로 이동 후 누르기 | 원인 표시, 돌아와도 이전 실패 명령 자동 실행 없음 |
| 7 | 전송 중 연결 끊기 | 재연결 후 실제 상태만 조회, 같은 명령 재전송 없음 |
| 8 | 폰 잠금 상태에서 누르기 | 잠금 해제 후에만 상태 변경 실행 |
| 9 | 등록되지 않은 두 번째 폰에서 GATT 쓰기 | 보호된 조회·명령 거부, 핫스팟 상태 변경 없음 |
| 10 | PC 재부팅 후 사용자 로그인 전후, 폰 블루투스 재연결 | 서비스 재등록, 저장된 등록 유지, 상태 조회 후 제어 가능 |
| 11 | AdGuard 켜진 폰, NordVPN 연결된 PC, 블루투스 이어폰 재생 중 사용 | BLE 제어 성공, 이어폰과 폰 인터넷 공유 정상 |
| 12 | 등록된 PC를 폰에서 페어링 해제 또는 PC에서 revoke | 이전 폰 제어 거부, 재등록 절차 필요 |

위 항목이 완료되기 전에는 실제 One UI 환경과 VPN 인터넷 공유까지 검증된 것으로 간주하지 않습니다. 제조사 BLE/GATT 동작, 잠금 해제 후 서비스 수명, 배터리 관리 설정 등의 실제 동작을 여기서 확인해야 합니다.

## 1.0.1 페어링 수정

실제 폰에서 번호 표시 전에 몇 초 후 페어링 취소가 보고되었습니다. 등록 모드를 열어도 PC의 번호 확인 요청이 발생하지 않은 상태를 확인했습니다. 1.0.0은 BLE 연결 전에 transport-AUTO `createBond()`를 호출했기 때문에 듀얼 모드 PC에서 Classic 연결을 시도할 가능성이 있었습니다. 1.0.1은 명시적인 LE GATT 연결을 먼저 열고 인증된 상태 조회를 통해 Android의 GATT 페어링을 진행합니다. 연결·조회 실패에는 단계/GATT 상태 코드도 표시합니다. 원인에 대한 추정과 실제 폰에서의 해결 확인은 구분해야 하며, 수정 APK의 폰 재검증은 아직 필요합니다.

PC에서는 번호 확인 요청 취소 후 같은 등록 창에서 재시도할 수 있도록 후보를 초기화했고, 이전 번호 화면의 승인이 새 요청에 적용되지 않도록 요청 ID를 확인합니다. 이 회귀 검증 4개를 추가하여 자동 테스트 총 22개가 통과했습니다.

## 1.0.2 업데이트 기능

자동 업데이트의 신규 버전 비교, 다운그레이드/동일 버전 무시, 지원 Android 버전 검사, 다른 호스트/HTTP/사용자정보가 들어간 URL 거부, 잘못된 해시와 초과 크기 거부를 JVM 테스트 5개로 검증합니다. Android 린트와 release 서명 검증도 실행합니다. 실제 폰에서 알림 허용, 이 출처 설치 허용, APK 설치 확인, 앱 재시작 후 등록 정보 유지, 백그라운드 작업 실행 및 실제 다음 버전 설치는 별도 확인이 필요합니다.
